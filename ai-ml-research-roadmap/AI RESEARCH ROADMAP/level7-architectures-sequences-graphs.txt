Level 7 · Modern Architectures: Sequences, Graphs and Transformers

Phase: Data Curation & Modeling Paradigms
Suggested duration: 30 sessions (~7 weeks)
Prerequisites: Level 6
Scope: Select and adapt architectures for language, time series, relational data, and long-context problems while connecting design choices to inductive bias.

M7.1 · Sequences, Time Series & Attention — (sessions: 5)
- Represent sequences with windows, masks, positional information, recurrence, convolution, and attention.
- Forecast or classify time-dependent data using time-aware splits and horizon-specific metrics.
- Identify temporal leakage caused by random splits, future features, and duplicated entities.
- Choose an architecture by matching inductive bias, computational complexity, and data structure to the research question.
- Measure memory, throughput, optimization stability, and long-context or structural failure cases alongside task scores.
Mental model: A sequence model should only use information that would have existed at prediction time.
Try: Compare a persistence baseline, recurrent model, temporal convolution, and attention model on one forecasting task.
Outcome: You can design honest experiments for sequential and time-dependent data.

M7.2 · Transformers and Language Modeling — (sessions: 6)
- Explain tokenization, embeddings, self-attention, masking, positional information, and next-token prediction.
- Implement a small transformer and inspect attention, loss, context length, and scaling behavior.
- Evaluate language models with task metrics, calibration, qualitative error analysis, and contamination awareness.
- Choose an architecture by matching inductive bias, computational complexity, and data structure to the research question.
- Measure memory, throughput, optimization stability, and long-context or structural failure cases alongside task scores.
Mental model: Attention is content-dependent information routing, not an automatic explanation of reasoning.
Try: Train a tiny language model on a permitted corpus and write a report on data, objective, and limitations.
Outcome: You can implement and reason about the core transformer training loop.

M7.3 · Graph Learning and Architecture Choice — (sessions: 4)
- Represent nodes, edges, attributes, graph splits, message passing, and inductive versus transductive settings.
- Compare graph convolution, graph attention, and simple non-graph baselines.
- Choose an architecture by data structure and scientific question rather than novelty alone.
- Choose an architecture by matching inductive bias, computational complexity, and data structure to the research question.
- Measure memory, throughput, optimization stability, and long-context or structural failure cases alongside task scores.
Mental model: An architecture is a prior about which relationships should influence a prediction.
Try: Build a graph benchmark with a leakage-safe edge or node split and compare it to feature-only models.
Outcome: You can adapt modern architectures to relational and structured data.

M7.4 · Complexity, Memory and Scaling Analysis — (sessions: 3)
- Compare time, memory, parameter, data, and communication complexity across architecture families.
- Measure throughput, latency, context behavior, and quality under matched hardware and data budgets.
Mental model: An architecture is a set of scientific trade-offs, not a leaderboard label.
Try: Create a scaling table that shows where each candidate becomes preferable.
Outcome: You can justify architecture choices with evidence beyond task accuracy.

M7.5 · Failure Modes and Structural Probes — (sessions: 3)
- Design synthetic probes for long-range dependence, compositionality, graph structure, order sensitivity, and extrapolation.
- Separate a representation failure from an optimization, data, or evaluation failure.
Mental model: A targeted probe makes a model’s inductive bias observable.
Try: Build two probes that distinguish memorization from structural generalization.
Outcome: You can test what an architecture has learned, not only whether it scores well.

M7.6 · Capstone: Architecture Selection Study — (sessions: 9)
- Define one task that can be represented as tabular, sequential, or relational data.
- Compare appropriate model families under matched data, compute, and tuning budgets.
- Connect each performance difference to an inductive bias, failure mode, or data property.
Final result: A comparative study that demonstrates architecture reasoning instead of architecture collecting.
