Level 12 · RAG & AI Agents

Phase: Scaled Systems & LLMs
Suggested duration: 36 sessions (~9 weeks)
Prerequisites: Level 11
Scope: Master advanced Retrieval-Augmented Generation (RAG), GraphRAG, Knowledge Graph embeddings, autonomous AI agent loops, multi-agent orchestration, neuro-symbolic reasoning, and the research methodology of studying vision-language models empirically.

M12.1 · Advanced Retrieval-Augmented Generation (RAG) Architecture — (sessions: 5)
Session 1 · Document parsing, chunking strategies & vector indexing
- Chunking Methodologies: Compare fixed-size chunking with sliding windows, recursive character splitting, semantic boundary chunking, and document hierarchy parsing.
- Embedding Spaces & Vector Databases: Benchmark dense embedding models (BGE, OpenAI, Cohere) against sparse BM25; configure vector indexing using HNSW and IVF-PQ.
Session 2 · Hybrid search & cross-encoder re-ranking
- Hybrid Search Synthesis: Combine dense semantic cosine similarity with sparse BM25 lexical scores using Reciprocal Rank Fusion (RRF) with tuned rank constants.
- Cross-Encoder Re-Ranking: Implement two-stage retrieval: rapid bi-encoder recall followed by cross-encoder re-ranking to compute joint query-document attention scores.
Mental model: RAG grounds probabilistic language generation in verified external documents, separating knowledge retrieval from language synthesis.
Try: Build a hybrid RAG pipeline combining BM25 and dense embeddings with a cross-encoder reranker, measuring retrieval precision@k and mean reciprocal rank (MRR).
Outcome: You can design, implement, and optimize multi-stage hybrid retrieval pipelines with vector databases and cross-encoder rerankers.

M12.2 · RAG Evaluation, Benchmarking & The RAG Triad — (sessions: 5)
Session 1 · The RAG Triad framework & hallucination diagnostics
- The RAG Triad: Deconstruct evaluation into Context Relevance (did retrieval find the right information?), Groundedness / Faithfulness (is the answer derived from context?), and Answer Relevance.
- Hallucination Auditing: Measure hallucination rates by checking token-level attribution and calculating semantic overlap between retrieved passages and generated claims.
Session 2 · Automated evaluation pipelines with Ragas & TruLens
- Automated RAG Evaluation: Build automated benchmark suites using Ragas and TruLens to compute quantitative Triad scores across diverse queries.
- Synthetic Test Set Generation: Generate question-context-answer ground truth evaluation datasets with verified citation links across simple, multi-hop, and reasoning queries.
Mental model: Evaluating RAG requires decoupling retrieval quality from generation quality; high accuracy cannot compensate for ungrounded hallucinated assertions.
Try: Evaluate a RAG system on 100 domain questions using Ragas, generate an automated diagnostic scorecard, and identify failure cases where retrieval succeeded but generation hallucinated.
Outcome: You can evaluate RAG pipelines quantitatively using the RAG Triad and build automated hallucination diagnostic suites.

M12.3 · Knowledge Graphs, GraphRAG & Neuro-Symbolic Reasoning — (sessions: 6)
Session 1 · Knowledge Graph construction & representation learning
- Graph Triples & Ontologies: Model knowledge as subject-predicate-object triples (h, r, t) using Resource Description Framework (RDF) and labeled property graphs in Neo4j.
- Knowledge Graph Embeddings: Formulate TransE (translational distance in embedding space), RotatE (relational rotations in complex vector space), and ComplEx for link prediction.
Session 2 · GraphRAG & hierarchical community summarization
- GraphRAG Architecture: Deconstruct Microsoft GraphRAG: extract entities and relations using LLMs, apply the Leiden algorithm for community detection, and generate hierarchical summaries.
- Global Sensemaking: Compare standard vector RAG against GraphRAG on holistic query understanding ("What are the overarching themes in this corpus?").
- Neuro-Symbolic Integration: Combine deterministic Cypher/SPARQL graph queries with neural generation to eliminate factual hallucination in structured domains.
Mental model: Knowledge graphs provide deterministic, symbolic truth structures that anchor neural models, combining logical precision with natural language fluency.
Try: Extract an entity-relation knowledge graph from an academic literature corpus, construct a GraphRAG index with community summaries, and benchmark global query answering against vector RAG.
Outcome: You can construct knowledge graphs, train link prediction embeddings, and build hierarchical GraphRAG systems for global corpus reasoning.

M12.4 · Autonomous AI Agents: ReAct, Planning & Tool Calling — (sessions: 6)
Session 1 · Agent cognitive architectures & ReAct loops
- Cognitive Architectures: Implement ReAct (Reasoning + Acting) loops: Thought -> Action -> Observation -> Reflection cycles for multi-step problem solving.
- Planning & Reflection: Implement Plan-and-Solve decomposition and Reflexion self-evaluating agents that store verbal lessons in episodic memory upon failure.
Session 2 · Tool calling mechanics & secure execution sandboxes
- Tool Schema Design: Define OpenAPI and JSON Schema tool specifications for calculators, database queries, and external APIs with strict parameter validation.
- Sandboxed Code Execution: Execute dynamic Python code safely within isolated Docker containers or WebAssembly runtimes with network and resource constraints.
Mental model: An AI agent is a language model situated in an environment with tools, memory, and feedback loops, iteratively executing actions to satisfy goals.
Try: Build an autonomous research agent in pure Python implementing a ReAct loop with tools for search, Python code execution in a Docker sandbox, and a local scratchpad memory.
Outcome: You can design autonomous agent loops, author strict tool schemas, and execute code safely in containerized sandboxes.

M12.5 · Multi-Agent Orchestration, State Machines & Agentic Benchmarking — (sessions: 5)
Session 1 · Multi-agent collaboration architectures
- Coordination Topologies: Implement supervisor-worker hierarchies, sequential pipelines, and multi-agent debate protocols where agents challenge each other's reasoning.
- State Machine Frameworks: Build complex cyclic agent workflows with LangGraph and AutoGen, managing persistent shared state, checkpoints, and human-in-the-loop approvals.
Session 2 · Agent evaluation benchmarks: SWE-bench & GAIA
- Standardized Agent Benchmarks: Evaluate autonomous agents on SWE-bench (resolving real GitHub issues), WebArena (web navigation), and GAIA (multimodal complex tasks).
- Failure Diagnostics: Measure agent failure modes: infinite execution loops, tool hallucination, context window exhaustion, and error cascading across sub-agents.
Mental model: Multi-agent systems decompose complex goals into specialized roles, using structured debate and state machines to catch individual reasoning errors.
Try: Build a two-agent research team (a literature researcher and a skeptical reviewer) in LangGraph that produces an annotated bibliography with verified citations through structured critique.
Outcome: You can orchestrate multi-agent workflows using state machines, manage persistent agent memory, and benchmark autonomous systems on standardized suites.

M12.6 · Capstone: Enterprise GraphRAG & Multi-Agent Autonomous Research Assistant — (sessions: 5)
Session 1 · Architecture & implementation of a hybrid research system
- Build an enterprise-grade GraphRAG index over a domain scientific corpus, combining dense vector embeddings, BM25 retrieval, and a Neo4j knowledge graph.
- Implement a multi-agent orchestration team consisting of a Query Planner, Graph Retrieval Agent, Python Data Analyst in a sandbox, and an Attribution Verifier.
Session 2 · Benchmarking, citation audit & scientific manuscript
- Evaluate the complete system on a 100-query domain benchmark, measuring RAG Triad metrics, citation accuracy, execution latency, and token cost.
- Author a 6-page research systems paper in LaTeX documenting the neuro-symbolic architecture, Leiden community detection results, and comparative retrieval benchmarks.
Final result: A fully operational Enterprise GraphRAG and multi-agent scientific research assistant with verified citation grounding, code execution sandboxes, and a technical paper.

M12.7 · Researching Vision-Language Models — (sessions: 4)
Session 1 · Designing controlled experiments on VLM capabilities and limitations
- VLM Capability Evaluation Protocol: Design a controlled evaluation study on a vision-language model (e.g. LLaVA, InternVL, Qwen-VL, or CogVLM) that separately evaluates visual perception (does the model correctly describe what is in the image?), cross-modal grounding (does the model correctly connect image regions to text spans?), and visual reasoning (does the model correctly reason about spatial relationships, counts, and relative attributes?) — using separate evaluation benchmarks for each capability (MME, MMBench, SeedBench) rather than a single aggregate score.
- VLM Hallucination Measurement: Measure object hallucination in a VLM using the CHAIR (Caption Hallucination Assessment with Image Relevance) metric: generate image captions for 500 images, compute the fraction of mentioned objects that do not appear in the image according to ground-truth COCO annotations, and compare hallucination rates across different decoding strategies (greedy, beam search, nucleus sampling with different temperatures).
- Multimodal vs Unimodal Ablation: Design an experiment that tests whether the visual component of a VLM actually contributes to performance on a visual question answering task: compare the full VLM against a text-only LLM given only the question (no image), a text-only LLM given the question plus a text description of the image, and the full VLM given the image — measuring the marginal contribution of visual input over text description.
Session 2 · Cross-modal alignment research and domain adaptation of VLMs
- Contrastive Pretraining Ablation for CLIP: Replicate a CLIP-style contrastive pretraining ablation from scratch on a small dataset: vary the batch size (128, 512, 2048), the temperature parameter (0.01, 0.07, 0.1), and the image and text encoder architecture (ViT-B/16 vs ResNet-50 vs ViT-S/8), measuring zero-shot classification accuracy and zero-shot retrieval Recall@1 as a function of each variable — following the ablation table structure of the original CLIP paper.
- Domain-Specific VLM Fine-Tuning Research: Design a study testing whether instruction fine-tuning a general-purpose VLM on a domain-specific visual QA dataset (e.g. medical image QA using VQA-RAD or PathVQA) improves domain accuracy without catastrophically forgetting general visual understanding: measure both domain benchmark accuracy and general VLM benchmark accuracy (MMBench) before and after fine-tuning, reporting the domain accuracy gain and the general capability degradation as separate metrics.
Mental model: Studying vision-language models scientifically requires decomposing the "VLM capability" claim into independently verifiable sub-skills — perception, grounding, and reasoning — and testing each separately, because a model can appear capable on an aggregate benchmark while actually relying on language shortcuts rather than genuine visual understanding.
Try: Evaluate LLaVA-1.6 on a visual question answering task using three conditions — (1) full VLM with image, (2) text-only LLM with image caption, (3) text-only LLM with question only — on 300 examples from the OKVQA benchmark; compute accuracy per condition, measure whether the image provides statistically significant information beyond the caption using McNemar's test, and compute the CHAIR hallucination rate on a 100-image caption generation evaluation.
Outcome: You can design controlled studies decomposing VLM capabilities into perception, grounding, and reasoning sub-tasks; measure object hallucination using CHAIR; design multimodal vs unimodal ablations; and evaluate domain fine-tuning tradeoffs using paired pre/post benchmark measurements.
