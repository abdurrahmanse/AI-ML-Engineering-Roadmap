Level 0 · Scientific Computing & Reproducible Research Foundations

Phase: Foundations & Methodology
Suggested duration: 13 sessions (~3 weeks)
Prerequisites: None (entry level for undergraduate researchers and beginning graduate students)
Scope: Establish the foundational research computing stack, reproducible environment management, seed determinism, experiment logging, and open-source scientific artifact standards.

M0.1 · The Research Computing Stack: Linux, Remote Servers & Shell Environments — (sessions: 2)
Session 1 · Linux Server Environments & Remote Access
- Navigate remote Linux compute servers via SSH with key-based authentication, config profiles, and persistent terminal multiplexers (tmux, screen).
- Manage background research processes with nohup, systemd user services, and process isolation tools (htop, ps, kill).
- Monitor GPU hardware metrics in real time using nvidia-smi, nvtop, and gpustat to diagnose GPU memory allocation and compute utilization.
Session 2 · Shell Scripting for Scientific Automation
- Write robust Bash automation scripts for parameterized batch execution, log redirection, and environment variable propagation.
- Handle data stream redirection with standard input, output, error streams, and Unix pipeline utilities (grep, awk, sed, cut).
- Automate remote file synchronization and dataset transfers between local machines and compute servers using rsync and scp.
Mental model: The research server is an experimental laboratory where tmux sessions preserve running experiments across network disconnects.
Try: Connect to a remote compute instance, launch a long-running simulation script inside a detached tmux session, and inspect memory allocation with nvidia-smi.
Outcome: Operate remote Linux research environments confidently, launch persistent jobs, and diagnose GPU allocation bottlenecks.

M0.2 · Reproducible Virtual Environments: Pixi, Conda, Docker & PyPI — (sessions: 2)
Session 1 · Environment Isolation & Dependency Resolution
- Understand the reproducibility crisis in machine learning research caused by unpinned transitive dependencies and varying CUDA runtime binaries.
- Isolate scientific Python environments using modern package managers (Pixi, uv, Conda) with locked dependency graphs.
- Compile and install C++/CUDA extensions from source within isolated environments without contaminating system libraries.
Session 2 · Containerization for Reproducible Research
- Author multi-stage Dockerfiles optimized for deep learning research containing specific CUDA, cuDNN, and PyTorch versions.
- Mount host scratch disks and dataset directories into containers while preserving file ownership and non-root execution permissions.
- Export locked environment manifests (environment.lock.yml, pyproject.toml) to ensure identical reproduction across compute clusters.
Mental model: A research environment must be an immutable, containerized artifact so that any researcher can reproduce exact numerical results five years later.
Try: Build a reproducible container image pinning PyTorch and CUDA runtime dependencies, mounting an external dataset volume.
Outcome: Eliminate dependency drift, resolve CUDA version mismatches, and package research code into containerized environments.

M0.3 · Version Control for Science: Git, Submodules & Open-Source Code Release — (sessions: 2)
Session 1 · Git Branching for Experimental Iteration
- Structure research Git repositories separating core libraries, model definitions, baseline benchmarks, and exploratory scripts.
- Use feature branches and semantic Git tags to mark paper submission checkpoints, rebuttal revisions, and camera-ready milestones.
- Manage external research repositories and upstream library forks cleanly using Git submodules and subtree merges.
Session 2 · Open-Source Code Standards & Research Hygiene
- Author comprehensive academic README files featuring installation commands, pretrained checkpoint links, and minimal reproduction snippets.
- Include open-source research licensing (MIT, Apache 2.0, CC-BY) and BibTeX citation blocks formatted for Google Scholar and ArXiv indexing.
- Prevent data leakage and credential exposure by strictly configuring .gitignore for checkpoints, logs, raw data, and secret keys.
Mental model: Git tags in research serve as immutable cryptographic stamps linking paper figures directly to specific commit hashes.
Try: Create a research template repository with a structured module layout, automated linter, .gitignore, and standardized BibTeX citation header.
Outcome: Structure academic research repositories to meet top-tier conference artifact evaluation and reproducibility standards.

M0.4 · Experiment Tracking & Artifact Management: Weights & Biases and MLflow — (sessions: 2)
Session 1 · Real-Time Metric Logging & Hyperparameter Tracking
- Integrate real-time experiment tracking tools (Weights & Biases, MLflow) into iterative training loops with minimal overhead.
- Log training and validation loss curves, evaluation accuracy, gradient norms, and learning rate schedules across continuous epochs.
- Structure hierarchical configuration dictionaries tracking all hyperparameters, random seeds, dataset versions, and model architectures.
Session 2 · Media Logging & Model Checkpoint Registry
- Log multimodal research artifacts including generated validation samples, confusion matrices, and interactive attention heatmaps.
- Implement an automated checkpoint saving strategy saving best-validation models, periodic epoch states, and emergency recovery snapshots.
- Compare experiment runs across multi-dimensional parallel coordinate plots to isolate hyperparameter sensitivities and performance gains.
Mental model: An experiment tracker is a digital laboratory notebook capturing the exact relationship between configuration deltas and empirical outcomes.
Try: Instrument a PyTorch training loop with Weights & Biases, logging scalar metrics, gradient norm histograms, and validation sample predictions.
Outcome: Systematically track hundreds of experimental runs, visualize metric trajectories, and maintain a centralized model registry.

M0.5 · Hardware Determinism, Random Seeds & Scientific Data Loaders — (sessions: 2)
Session 1 · Eliminating Sources of Non-Determinism
- Identify hardware and software sources of numerical non-determinism in deep learning (CUDA atomic operations, cuDNN benchmarking, CPU threading).
- Implement deterministic initialization routines seeding Python random, NumPy, PyTorch CPU/GPU generators, and cuDNN deterministic flags.
- Understand the performance trade-offs of enabling torch.use_deterministic_algorithms() during initial prototyping versus large-scale runs.
Session 2 · High-Throughput Scientific Data Pipelines
- Build multi-worker PyTorch DataLoaders with custom worker initialization functions ensuring independent, deterministic worker random states.
- Avoid common multiprocessing pitfalls in PyTorch data loaders such as shared memory exhaustion, worker deadlocks, and duplicate augmentations.
- Implement memory-mapped dataset formats and pre-fetching pipelines (Arrow, WebDataset, HDF5) to prevent CPU data starvation during GPU training.
Mental model: True scientific reproducibility requires that rerunning a script with seed 42 produces identical bitwise loss values across epochs.
Try: Write a deterministic seed utility function, verify that two independent training runs produce identical loss curves, and benchmark data loader throughput.
Outcome: Eliminate stochastic noise between runs, guarantee experimental determinism, and design high-throughput scientific data pipelines.

M0.6 · Capstone Project: Reproducible Experiment Harness & Pipeline Template — (sessions: 3)
Session 1 · Architectural Scaffold & Experiment Configuration
- Design a modular, object-oriented experiment harness decoupling dataset loading, model architecture, training loop, and evaluation metrics.
- Implement structured configuration parsing with type validation and command-line overrides (Hydra, Pydantic, argparse).
- Create automated logging hooks capturing Git commit hash, environment diff, hardware specifications, and package versions at runtime start.
Session 2 · Verification, Checkpointing & Open-Source Packaging
- Build a resilient training loop featuring automated checkpoint resumption, anomaly detection for NaN gradients, and graceful signal handling.
- Author an automated smoke-test suite verifying forward pass, backward gradient flow, and data pipeline throughput on dummy synthetic tensors.
- Package the harness into a reusable research template repository with complete documentation, container definition, and continuous integration.
Mental model: A battle-tested research harness is a scientist's primary laboratory apparatus, reducing the time from new hypothesis to empirical result from weeks to hours.
Try: Run the experiment harness with multiple configuration overrides, simulate a mid-training process termination, and verify seamless resumption from checkpoint.
Outcome: Possess a production-grade, conference-ready scientific research template that ensures complete reproducibility across all subsequent projects.

CAPSTONE PROJECT: Reproducible Experiment Harness & Pipeline Template
BRIEF: Build a standardized, publication-ready research scaffolding framework in PyTorch that guarantees bitwise reproducibility, tracks real-time experimental metrics, handles graceful checkpoint recovery, and exports complete environment provenance for academic code releases.
Build an experiment harness that:
- Initializes deterministic random generators across Python, NumPy, and PyTorch backends with verified seed propagation to DataLoader worker processes.
- Parses hierarchical experiment configurations via structured configuration schemas with strict type validation and runtime command-line overrides.
- Logs scalar metrics, gradient norm distributions, learning rate schedules, and validation artifacts to Weights & Biases and local disk simultaneously.
- Detects NaN/Inf loss values and exploding gradients instantly, triggering informative debug dumps with tensor activation statistics.
- Implements atomic checkpoint saving with metadata sidecars recording validation metrics, optimizer states, learning rate schedules, and Git commit hashes.
- Automatically resumes interrupted training runs from the latest checkpoint without metric duplication or data epoch leakage.
- Features a unit test suite validating gradient propagation, deterministic outputs under fixed seeds, and data pipeline memory bounds.
Deliverables:
- Modular research repository featuring decoupled datasets/, models/, training/, and configs/ directories.
- Verified Dockerfile and environment lockfile reproducing the exact runtime on any CUDA-enabled system.
- An interactive Weights & Biases dashboard comparing multiple runs with distinct seeds and hyperparameter configurations.
- Comprehensive academic README with step-by-step reproduction instructions, checkpoint links, and BibTeX citation.
Outcome: You can scaffold any machine learning research project with industrial-grade scientific rigor, guaranteed reproducibility, and frictionless collaboration.
