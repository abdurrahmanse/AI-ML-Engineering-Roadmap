Level 4 · Deep Learning Research Prototyping in PyTorch & JAX

Phase: Research Prototyping
Suggested duration: 13 sessions (~3 weeks)
Prerequisites: Level 3 (Experimental Design & Rigorous Benchmarking)
Scope: Master the engineering craft of deep learning research prototyping: building modular research codebases, implementing custom autograd operators, mastering numerical precision (BF16/FP16), custom loss surgery, and hardware memory profiling in PyTorch and JAX.

M4.1 · Modular Research Codebase Architecture: PyTorch Lightning & Clean JAX — (sessions: 2)
Session 1 · Modular Research Architecture in PyTorch
- Decouple research components into clean object-oriented modules: LightningDataModule, LightningModule, and custom Callback hooks.
- Structure model codebases with clear abstraction boundaries between foundational backbone networks, projection heads, and loss functions.
- Eliminate training boilerplate using PyTorch Lightning while preserving low-level control over optimizer steps, gradient clipping, and manual backward passes.
Session 2 · Functional Research Prototyping in JAX & Equinox
- Understand pure functional programming paradigms in JAX: stateless transformations, explicit pseudo-random key management (jax.random.split), and PRNG keys.
- Implement neural network research modules using Equinox or Flax, manipulating pytrees and pure functional layers cleanly.
- Master just-in-time compilation (jax.jit), automatic vectorization (jax.vmap), and automatic reverse-mode autodiff (jax.grad, jax.value_and_grad).
Mental model: A clean research codebase allows you to swap an entire attention mechanism or loss formulation with a single configuration flag.
Try: Implement a custom multi-layer perceptron in both PyTorch and JAX, verifying that both implementations yield identical outputs and gradients on dummy data.
Outcome: Structure modular, extensible research codebases in both PyTorch and JAX, decoupling modeling logic from infrastructure code.

M4.2 · Extending Autograd: Custom Forward-Backward Operators & Matrix Derivatives — (sessions: 2)
Session 1 · Custom Autograd Operators in PyTorch
- Implement custom PyTorch differentiable operations by subclassing torch.autograd.Function with explicit forward and backward static methods.
- Save necessary intermediate activation tensors using ctx.save_for_backward() while avoiding memory leaks and circular reference references.
- Derive and implement backward vector-Jacobian products (VJPs) for novel custom matrix and tensor operations.
Session 2 · Numerical Gradient Verification & Edge Cases
- Verify custom backward gradient implementations against finite-difference approximations using torch.autograd.gradcheck().
- Handle non-differentiable points and subgradient approximations (e.g., custom activations, clamped gradients, straight-through estimators).
- Custom VJPs and custom JVP primitives in JAX using jax.custom_vjp and jax.custom_jvp for custom mathematical primitives.
Mental model: Autograd functions allow a researcher to introduce non-standard mathematical operators into neural networks while maintaining full end-to-end differentiability.
Try: Implement a custom normalized Euclidean distance layer by subclassing torch.autograd.Function, and pass gradcheck with strict tolerance.
Outcome: Author custom differentiable operators, derive analytical vector-Jacobian products, and verify numerical gradient accuracy.

M4.3 · Numerical Stability, Mixed Precision (BF16/FP16) & Loss Scaling — (sessions: 2)
Session 1 · Numerical Precision & Floating-Point Arithmetic
- Understand IEEE 754 floating-point representations: dynamic range, exponent bits, and mantissa bits in FP32, FP16, and BF16.
- Identify the root causes of numerical instability in research models: catastrophic cancellation, underflow, overflow, and division by zero.
- Implement numerically stable primitives: the log-sum-exp trick for Softmax, epsilon clamps in denominators, and safe cross-entropy losses.
Session 2 · Automated Mixed Precision & Loss Scaling
- Implement mixed-precision training in PyTorch using torch.amp.autocast() with BF16 on modern hardware (Ampere, Hopper).
- Apply torch.amp.GradScaler() when using FP16 to dynamically scale small gradient magnitudes and prevent zero-underflow during backward passes.
- Diagnose and debug NaN/Inf generation during training by attaching gradient hooks and using torch.autograd.set_detect_anomaly(True).
Mental model: BF16 trades precision for dynamic range, matching FP32's exponent bits and eliminating the need for delicate loss scaling.
Try: Trigger an intentional numerical underflow in a custom Softmax function, observe NaN loss values, and rewrite it using the stable log-sum-exp formulation.
Outcome: Train deep models stably in mixed precision (BF16/FP16), eliminate NaN loss crashes, and master floating-point numerical stability.

M4.4 · Custom Loss Formulations, Regularization Penalties & Gradient Surgery — (sessions: 2)
Session 1 · Custom Objective Functions & Multi-Task Losses
- Implement advanced custom loss objectives: focal loss, contrastive InfoNCE, cosine margin losses, and Wasserstein distance approximations.
- Balance multi-task loss objectives dynamically using learned task weights, homoscedastic uncertainty weighting, or gradient normalization (GradNorm).
- Add custom spectral regularizers (Frobenius norms, nuclear norm penalties, orthogonal weight constraints) directly to loss expressions.
Session 2 · Gradient Surgery & Optimization Modifications
- Implement gradient clipping by norm (torch.nn.utils.clip_grad_norm_) and gradient clipping by value to stabilize deep networks.
- Apply gradient surgery techniques: projected gradient descent, gradient projection to mitigate conflicting task gradients (PCGrad).
- Inspect layer-wise gradient norms during training to diagnose vanishing gradients in early layers or exploding gradients in attention heads.
Mental model: The loss function is a researcher's steerage mechanism; gradient surgery ensures that competing loss terms do not destructively cancel each other out.
Try: Implement the PCGrad algorithm to project conflicting multi-task gradients onto the normal plane of conflicting tasks, verifying improved multi-task stability.
Outcome: Formulate novel loss functions, balance multi-objective optimization, and apply gradient surgery to resolve training instabilities.

M4.5 · Research Performance Profiling: Memory Snapshots, CUDA Streams & FLOP Counters — (sessions: 2)
Session 1 · GPU Memory Profiling & Snapshot Analysis
- Differentiate between allocated GPU memory, cached reserved memory, and peak memory usage using torch.cuda.memory_allocated() and memory_reserved().
- Capture and inspect interactive HTML memory snapshots using torch.cuda.memory._record_memory_history() to pinpoint activation memory spikes.
- Apply activation checkpointing (gradient checkpointing) to trade off recomputation compute for dramatic GPU memory footprint reductions.
Session 2 · Execution Bottleneck Profiling & FLOP Counting
- Profile model execution bottlenecks using torch.profiler, identifying CPU-GPU synchronization stalls, kernel launch latencies, and CUDA idle bubbles.
- Count exact floating-point operations (FLOPs) and parameter counts using fvcore, deepspeed.profiling, or torch_tb_profiler.
- Optimize asynchronous CUDA memory transfers by utilizing non-blocking tensor copies, pinned host memory, and dedicated CUDA streams.
Mental model: Profiling reveals the true hardware cost of your architectural innovation, turning abstract computational complexity into concrete milliseconds and gigabytes.
Try: Profile a model with torch.profiler, identify a CPU-bound data loading bottleneck, and resolve it using pinned memory and non-blocking CUDA transfers.
Outcome: Profile GPU memory and execution latencies rigorously, eliminate compute bottlenecks, and optimize research code for high throughput.

M4.6 · Capstone Project: Extensible Deep Learning Research Testbed with Custom Operators — (sessions: 3)
Session 1 · Architecture & Custom Differentiable Modules
- Design a modular, extensible PyTorch research testbed featuring a custom attention layer implemented via torch.autograd.Function.
- Implement mathematically derived vector-Jacobian products in the backward pass, passing rigorous numerical gradcheck verification.
- Incorporate mixed precision (BF16/FP16) support with automatic detection of hardware capabilities and stable gradient scaling.
Session 2 · Profiling, Checkpointing & Scientific Verification
- Integrate memory snapshot capture hooks that automatically record and export memory allocation profiles during peak forward/backward passes.
- Implement activation checkpointing across deep layers, benchmarking exact memory savings versus wall-clock training throughput trade-offs.
- Package the testbed with automated unit tests for numerical stability, gradient correctness, and reproducible metric outputs across random seeds.
Mental model: A researcher who can build, customize, and profile their own PyTorch operators from scratch is never limited by existing library abstractions.
Try: Run the research testbed, capture an interactive memory snapshot during training, and demonstrate a 40% memory reduction with activation checkpointing.
Outcome: Build production-grade, highly optimized deep learning research architectures with custom autograd operators and detailed hardware profiling.

- Provides a clean PyTorch Lightning or clean modular PyTorch interface for seamless integration into downstream research projects.
Deliverables:
- Extensible, fully commented Python module containing the custom operator and testbed implementation.
- Unit test suite validating gradient correctness, numerical stability under extreme inputs, and multi-seed determinism.
