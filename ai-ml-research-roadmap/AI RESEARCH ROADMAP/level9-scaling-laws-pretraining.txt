Level 9 · High-Performance Computing (HPC) & Scaled Research Systems

Phase: HPC, Scaling & Interpretability
Suggested duration: 13 sessions (~3 weeks)
Prerequisites: Level 8 (Benchmark Creation, Data Curation & Evaluation Science)
Scope: Master the computational infrastructure of modern large-scale machine learning research: operating on HPC supercomputing clusters with SLURM, distributed communication primitives (NCCL), multi-GPU training (DDP, FSDP), 3D parallelism (Megatron-LM, ZeRO-3), and measuring Model FLOPs Utilization (MFU).

M9.1 · Supercomputing Cluster Architecture: SLURM Schedulers, Modules & InfiniBand Fabrics — (sessions: 2)
Session 1 · Supercomputing Cluster Architecture & SLURM
- Understand high-performance computing (HPC) cluster topologies: login nodes, compute nodes, shared Lustre/GPFS parallel filesystems, and scratch storage.
- Manage cluster resource allocation using the SLURM workload manager: sbatch scripts, srun interactive allocations, squeue monitoring, and scancel.
- Configure SLURM job submission parameters: GPU counts (--gpus-per-node), CPU cores, memory limits, job arrays, and dependency chains.
Session 2 · Environment Modules & High-Speed Interconnects
- Load and configure environment modules (Lmod) to access specific CUDA toolkits, cuDNN libraries, OpenMPI distributions, and compiler toolchains.
- Understand high-speed cluster networking fabrics: InfiniBand (HDR, NDR), RoCE, Non-Uniform Memory Access (NUMA), and PCIe Gen4/Gen5 lane topology.
- Measure inter-node and intra-node network latency and bandwidth using nccl-tests and InfiniBand diagnostics (ibv_devinfo, ib_write_bw).
Mental model: A supercomputer is not just many servers; it is a single, tightly coupled distributed instrument synchronized across a low-latency network fabric.
Try: Write a multi-GPU SLURM batch submission script requesting 4 GPUs on a single node, redirecting stdout/stderr, and verifying environment module initialization.
Outcome: Operate on university and national supercomputing clusters using SLURM, manage HPC modules, and diagnose interconnect topologies.

M9.2 · Collective Communication Primitives: Ring All-Reduce, NCCL & Hardware Topologies — (sessions: 2)
Session 1 · Distributed Communication Primitives
- Formalize distributed collective communication operations: Broadcast, Scatter, Gather, All-Gather, Reduce, Reduce-Scatter, and All-Reduce.
- Derive the communication volume and time complexity of the Ring All-Reduce algorithm across N participating compute ranks.
- Prove that Ring All-Reduce transfers exactly 2 * ((N - 1) / N) * S bytes per GPU, making communication bandwidth independent of cluster size N.
Session 2 · NVIDIA Collective Communications Library (NCCL)
- Understand the role of NCCL as the high-performance communication backbone for multi-GPU PyTorch training.
- Configure NCCL ring and tree communication topologies across NVLink bridges within nodes and InfiniBand adapters between nodes.
- Debug distributed communication stalls and deadlocks using NCCL debug environment variables (NCCL_DEBUG=INFO, NCCL_DEBUG_SUBSYS=ALL).
Mental model: Ring All-Reduce splits gradient tensors into chunks that flow in a circle; every GPU sends and receives simultaneously without a master bottleneck.
Try: Run an nccl-tests all_reduce_perf benchmark across multiple GPUs, measure effective bus bandwidth (GB/s), and verify near-theoretical saturation.
Outcome: Derive collective communication algorithms analytically, configure NCCL parameters, and diagnose distributed communication bottlenecks.

M9.3 · Distributed Data Parallel (DDP) & Fully Sharded Data Parallel (FSDP) — (sessions: 2)
Session 1 · Distributed Data Parallel (DDP) Internals
- Master the execution mechanics of torch.nn.parallel.DistributedDataParallel (DDP): process forking, rank assignments, and local rank mapping.
- Understand gradient bucketing and overlapping: how DDP initiates asynchronous Ring All-Reduce operations while earlier layers are still computing gradients.
- Implement robust distributed initialization with torch.distributed.init_process_group() using the NCCL backend and DistributedSampler.
Session 2 · Fully Sharded Data Parallel (FSDP)
- Analyze the memory wall of standard DDP: redundant replication of model weights, optimizer states, and gradients across every GPU rank.
- Implement Fully Sharded Data Parallel (FSDP): sharding model parameters, gradients, and optimizer states across ranks, reconstructing weights on the fly.
- Configure FSDP sharding strategies (FULL_SHARD, SHARD_GRAD_OP, NO_SHARD), CPU offloading, and mixed-precision communication policies.
Mental model: DDP replicates the model everywhere and syncs gradients; FSDP shreds the model across GPUs and gathers layers just in time for execution.
Try: Convert a standard PyTorch training loop into a multi-GPU FSDP script, and train a model whose parameter count exceeds single-GPU VRAM capacity.
Outcome: Deploy multi-GPU training with PyTorch DDP and FSDP, overlapping compute with communication and breaking single-GPU memory barriers.

M9.4 · 3D Parallelism: Tensor Parallelism, Pipeline Parallelism & ZeRO-1/2/3 Memory Sharding — (sessions: 2)
Session 1 · Zero Redundancy Optimizer (DeepSpeed ZeRO)
- Deconstruct the exact memory consumption of AdamW optimizer states (16 bytes per parameter in mixed precision).
- Differentiate the three stages of ZeRO: ZeRO-1 (shards optimizer states), ZeRO-2 (shards optimizer states + gradients), and ZeRO-3 (shards everything).
- Implement ZeRO memory reduction using DeepSpeed or native PyTorch FSDP, calculating exact per-GPU memory footprints across cluster sizes.
Session 2 · 3D Parallelism: Tensor & Pipeline Parallelism (Megatron-LM)
- Master Megatron-LM Tensor Parallelism: column-parallel linear projections for Q, K, V and row-parallel projections for output matrices.
- Master Pipeline Parallelism: partitioning model layers sequentially across GPU stages with micro-batching to minimize pipeline bubbles (1F1B schedule).
- Understand 3D Parallelism combinations: uniting Data Parallelism (DP), Tensor Parallelism (TP), and Pipeline Parallelism (PP) for frontier model scales.
Mental model: Tensor Parallelism splits individual matrices across fast NVLink; Pipeline Parallelism splits layers across nodes; Data Parallelism scales across clusters.
Try: Calculate the theoretical memory footprint of a 20B parameter model under ZeRO-1, ZeRO-2, and ZeRO-3 across an 8-GPU node.
Outcome: Architect large-scale 3D distributed training configurations combining Tensor, Pipeline, and Sharded Data Parallelism.

M9.5 · Compute Efficiency Metrics: Model FLOPs Utilization (MFU) & Hardware Profiling — (sessions: 2)
Session 1 · Theoretical vs. Hardware FLOPs Utilization
- Compute theoretical minimum FLOPs required for forward and backward passes of a Transformer: 6 * N * D (where N is parameters, D is tokens).
- Define Hardware FLOPs Utilization (HFU): the percentage of raw hardware peak floating-point capacity achieved by the cluster during execution.
- Define Model FLOPs Utilization (MFU, Chowdhery et al.): the ratio of theoretical model FLOPs to peak hardware capacity, penalizing recomputation overhead.
Session 2 · Profiling Distributed Training Efficiency
- Instrument distributed training runs to calculate and log real-time MFU, achieving target research efficiency benchmarks (MFU > 45-55%).
- Identify causes of low MFU: communication bubbles, activation recomputation overhead, CPU data loading starvation, and memory bandwidth throttling.
- Monitor power consumption, thermal throttling, and calculate the carbon footprint (CO2 equivalent) of large-scale scientific training experiments.
Mental model: MFU is the supreme benchmark of research systems engineering: it tells you what percentage of your expensive compute budget was genuinely useful math.
Try: Write an MFU tracking callback that calculates floating-point throughput at every step, and measure the exact MFU of a distributed training run.
Outcome: Compute MFU and HFU rigorously, profile distributed cluster efficiency, and optimize GPU utilization to maximize scientific output per dollar.

M9.6 · Capstone Project: Multi-Node Distributed Training Harness with MFU Benchmarking — (sessions: 3)
Session 1 · Distributed Harness Architecture & SLURM Integration
- Construct an industrial-grade distributed training framework supporting PyTorch FSDP and Megatron-style Tensor Parallelism across multiple nodes.
- Author robust SLURM job submission scripts with automated node discovery, master address extraction, and environment variable initialization.
- Implement fault-tolerant distributed checkpointing using PyTorch Distributed Checkpoint (torch.distributed.checkpoint) with asynchronous saving.
Session 2 · Benchmarking, Scaling Studies & Efficiency Profiling
- Execute a weak scaling and strong scaling benchmark study across 1, 2, 4, and 8 GPUs on an HPC supercomputing cluster.
- Measure and plot exact MFU, throughput (tokens/second), and communication-to-computation ratios across increasing cluster node counts.
- Author a systems research report in LaTeX detailing scaling efficiency, communication overhead, and optimal distributed configurations.
Mental model: A master of scaled systems turns raw hardware clusters into a transparent scientific accelerator, executing experiments that smaller labs cannot attempt.
Try: Launch a multi-GPU FSDP training job on a compute cluster, achieve an MFU exceeding 45%, and verify distributed checkpoint resumption.
Outcome: Deploy, optimize, and profile large-scale distributed training on HPC supercomputing clusters, achieving state-of-the-art computational efficiency.

CAPSTONE PROJECT: Multi-Node Distributed Training Harness with MFU Benchmarking

Build a distributed research harness that:
- Implements a modern Transformer architecture trained using PyTorch Fully Sharded Data Parallel (FSDP) with configurable sharding strategies.
- Operates seamlessly across multi-GPU and multi-node clusters via torchrun and SLURM batch job scripts with dynamic rank and address resolution.
- Integrates asynchronous distributed checkpointing (torch.distributed.checkpoint), saving and loading sharded model weights without gathering to a single rank.

- Implements an automated scaling benchmark suite that evaluates throughput (tokens/second) across 1, 2, 4, and 8+ GPUs under both strong and weak scaling.
- Detects straggling GPU workers and communication bottlenecks by recording detailed NCCL timing telemetry and memory snapshots.
- Implements mixed-precision communication policies (reducing inter-node gradient communication bandwidth with BF16 gradients).
- Generates publication-ready scaling plots (linear speedup vs. ideal scaling) and a LaTeX systems engineering summary table.
Deliverables:
- Modular distributed codebase featuring distributed/fsdp_wrapper.py, metrics/mfu_tracker.py, and slurm/submit_multinode.sh.
- Scalability benchmark report with vector plots illustrating strong and weak scaling efficiency and MFU across cluster sizes.
- Detailed technical runbook documenting SLURM deployment, NCCL troubleshooting, and optimal batch-size/sharding configurations.
Outcome: You can orchestrate large-scale deep learning experiments on supercomputing clusters, achieve high MFU efficiency, and break through computational limits.
