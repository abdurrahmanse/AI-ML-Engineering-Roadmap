Level 0 · Scientific Computing & Python

Phase: Research Foundations
Suggested duration: 24 sessions (~6 weeks)
Prerequisites: None; designed for a complete beginner entering scientific computing
Scope: Build the foundational computing, Linux shell, Python programming, unit testing, and containerized laboratory environment setup required to conduct reproducible research without relying on tutorial code.

M0.1 · Command-Line Foundations, Linux Shell & Remote Laboratory Work — (sessions: 4)
Session 1 · Linux filesystem, shell navigation & process control
- Prerequisites & Foundations: Explain how operating systems coordinate processes, memory, file descriptors, and remote network streams during scientific computation.
- Command-Line Operations: Navigate Linux filesystems, manage process priority with nice, inspect resource usage with htop, and manage background execution with tmux.
Session 2 · Remote server workflows, SSH & credential security
- Remote Laboratory Access: Configure SSH key pairs, edit ssh config files, manage persistent remote sessions, and transfer datasets with rsync and scp.
- Security & Credential Hygiene: Isolate credentials in non-committed environment variables, configure gitignore, and sanitize secret keys from terminal history.
Mental model: The terminal is an exact scientific instrument; every command should be predictable, auditable, and documented in your laboratory log.
Try: Set up a remote Linux virtual machine or container, configure SSH keys, create a project directory hierarchy, and transfer a sample dataset using rsync.
Outcome: You can independently navigate Linux environments, manage background computing jobs, and execute remote laboratory tasks securely.

M0.2 · Research-Grade Python Programming & Memory-Aware Vectorization — (sessions: 4)
Session 1 · Data structures, functional programming & type safety
- Core Language Mechanics: Write idiomatic Python using list and dictionary comprehensions, generators, custom iterators, and immutable data structures.
- Type Annotations & Clean Code: Apply type hints with typing and dataclasses, document functions with NumPy-style docstrings, and enforce static verification with mypy.
Session 2 · Vectorized numerical computation with NumPy
- Memory Layout & Strides: Understand contiguous memory layouts (C-order vs Fortran-order), tensor dimensions, array slicing, and avoid slow Python-level loops.
- Broadcasting & Numerical Verification: Master array broadcasting rules, vector operations, and compare hand-derived calculations against vectorized implementations.
Mental model: Scientific Python is not just syntax; it is the discipline of mapping abstract mathematical operations into memory-efficient, cache-friendly vector instructions.
Try: Implement a multi-dimensional Euclidean pairwise distance matrix from scratch using pure Python loops, then reimplement it with NumPy broadcasting and measure the 50x speedup.
Outcome: You can write robust, vectorized, and type-annotated Python code suitable for scientific research workflows.

M0.3 · Software Engineering for Researchers: Testing, Debugging & Profiling — (sessions: 4)
Session 1 · Automated unit testing with pytest
- Test-Driven Research Habits: Write parameterized unit tests with pytest to verify numerical edge cases, empty datasets, and invalid feature dimensions.
- Property-Based Testing: Use hypothesis to generate random inputs and verify mathematical invariants such as matrix symmetry, non-negativity, and triangle inequality.
Session 2 · Interactive debugging & code profiling
- Interactive Debugging: Step through failing execution graphs using pdb and breakpoint, inspecting stack frames, local variables, and tensor shapes.
- Computational Profiling: Profile code bottlenecks using cProfile and line_profiler to isolate memory allocations and expensive subroutines before training models.
Mental model: A research script without automated unit tests is an uncalibrated measuring tool whose experimental outputs cannot be trusted.
Try: Write a data preprocessing function with five deliberate edge-case failures, then write a pytest suite that catches each failure and asserts proper exception handling.
Outcome: You can systematically debug, profile, and unit-test scientific Python code to ensure software correctness.

M0.4 · Version Control, Experiment Logs & Lab Notebooks — (sessions: 4)
Session 1 · Git branching models for empirical research
- Version Control Disciplines: Initialize Git repositories, write conventional atomic commit messages, and manage branches for distinct experimental hypotheses.
- Collaborative Workflows: Submit pull requests, conduct peer code reviews on research implementations, and diff Jupyter notebooks cleanly using nbdime.
Session 2 · Scientific experiment logging & provenance
- Laboratory Notebook Keeping: Maintain a dated research log recording hypothesis motivations, hardware configurations, exact random seeds, and failed attempts.
- Provenance Tracking: Bind Git commit hashes and parameter dictionaries to every generated figure, table, and checkpoint file to guarantee full auditability.
Mental model: A scientific Git history is the legal record of your experimental reasoning, preserving every hypothesis and decision made during a study.
Try: Publish an open-source research template repository on GitHub with clean branch history, automated GitHub Actions CI, and an informative README.
Outcome: You can manage research software collaboratively with Git and maintain complete provenance across experimental iterations.

M0.5 · Environment Locking, Containerization & Artifact Reproducibility — (sessions: 4)
Session 1 · Deterministic dependency locking
- Package Isolation: Configure isolated environments with uv or conda, specifying exact Python minor versions and system-level dependencies.
- Deterministic Lockfiles: Generate frozen lockfiles (pyproject.toml or conda-lock) that pin package hashes and wheel builds to prevent dependency drift.
Session 2 · Containerization with Docker & Singularity
- Docker Containerization: Write reproducible multi-stage Dockerfiles specifying base CUDA drivers, non-root user permissions, and entrypoint scripts.
- HPC Container Portability: Build Singularity/Apptainer images for high-performance computing clusters where root container execution is restricted.
Mental model: Software reproducibility means another researcher on a different continent and operating system can reproduce your exact computational environment in one command.
Try: Containerize a Python numerical benchmark using Docker, mount a local data directory, run the script inside the container, and verify identical outputs.
Outcome: You can build, lock, and containerize reproducible research environments across workstations and shared compute clusters.

M0.6 · Capstone: Reproducible Research Laboratory Environment & Experiment Harness — (sessions: 4)
Session 1 · Modular experiment harness architecture
- Build a modular, object-oriented experiment harness featuring decoupled configuration parsing, automated smoke testing, and deterministic seeding.
- Integrate automated CLI argument validation, system metrics logging (CPU/RAM/GPU memory), and clean output directory structuring (data, logs, figures).
Session 2 · End-to-end containerized verification
- Package the entire experimental harness inside a Docker container with an automated Makefile and comprehensive documentation.
- Execute a full smoke test from a clean environment on a secondary machine, verifying that outputs match bit-for-bit with stored golden artifacts.
Final result: A fully reproducible, tested, and containerized research laboratory harness that serves as the foundation for all subsequent machine learning studies.
